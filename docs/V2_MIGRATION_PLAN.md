# MISSION CONTROL 2.0 migration and delivery plan

This is a proposal awaiting implementation approval. The workspace is a React 19 + TypeScript 6 + Vite 8 project as confirmed by the manifest, lockfile and installed packages. Inspected the handwritten source and CSS, simulation and game modules, test suite, app/tooling entry points, project docs and reference packet. The three supplied PDFs were reviewed during the original [source audit](SOURCE_AUDIT.md). All 12 existing tests passed on Node 24.22.0 in this review. This workspace lacks Git metadata, so establish a baseline commit or source archive before changing the implementation.

## Existing project and reuse

| Area reviewed | Reuse and migration risk |
| --- | --- |
| `src/simulation/catalog.ts`, `types.ts`, `launch.ts` | Preserve as legacy. Extract patterns for immutable data, compatible sensor checks and typed diagnostics. V1 grams, watt-minutes, MB and credits require explicit boundaries from V2 kg, J, bit counts and USD cents. Authored orbit profiles cannot migrate as orbital state. |
| `simulate.ts`, `findings.ts`, `compare.ts` | Preserve deterministic entrypoints, evidence-based findings and same-brief comparison. V1 assumes fixed time slots, one camera with fixed-size FIFO products, full initial charge and one optional action per step. Do not extend its score or types into the V2 physical model. |
| `tests/simulation.test.ts` | Keep the full legacy suite and its original expectations, including the 13 versus 9 crop comparison and catalog sweep. The overlap fixture temporarily mutates an exported catalog. V2 scenarios should use injected immutable test fixtures for concurrent workers. |
| `src/App.tsx`, `main.tsx`, `src/game/Briefing.tsx`, `Designer.tsx` | Reuse the static app shell, focus pattern, input cards, inline blockers, and mission-led brief. Current stage, design and prior attempt are ephemeral within the React tree. A routed or state-driven V2 shell needs resumable context and distinct draft/commit/review states. |
| `Operations.tsx`, `Results.tsx`, `Visuals.tsx` | Reuse playback controls, accessible meter and event UI, debrief and source disclosure. Clock currently advances a fixed cursor with an interval, and cumulative metrics are recomputed from slices. For longer runs use worker-produced snapshots and cumulative samples. The SVG orbit is schematic and suitable as a legacy visual. V2 fallback uses projected physical samples. |
| CSS, index, package/config and assets | Reuse base colors and responsive form behavior. Split workspace styles as complexity grows. App tsconfig does not explicitly require strict mode. Introduce strict V2 boundaries while protecting legacy. No 3D dependencies installed at review. Identify unused starter assets during later cleanup. |
| `docs/` and `references/` | Keep V1 design, source audit and tests as a historical baseline. Use the local challenge and submission notes when relevant. The V2 documents describe the next architecture. Screenshot controls and labels informed the design analysis. |

There are no persisted V1 saves to upgrade. Keep the legacy entry available, and begin V2 with its own first schema and namespace. Version the envelope, component catalog, environment and solver independently. Keep old manifests replayable with the original dependencies or explicitly present an archived read-only review if a dependency is unavailable. Add new test entry points without narrowing legacy coverage.

## Phases and release gates

| Phase | Deliverable and acceptance | Dependencies |
| --- | --- | --- |
| 0 · Agency foundation and verification harness | Create/name an agency, select a training contract and schedule a research unlock. Ledger reconciliation is exact across reserve, payment, release, reload and repeated settlement. Test backup, import migration and competing-tab conflict. Establish independent orbit fixture workflow and SI/frame/time contracts. Run all legacy tests. | Confirm product targets and establish source baseline. |
| 1 · 3D assembly | Small Earth catalog, interlocking node tree and viewport. Attach/rotate/remove and undo/redo with pointer, keyboard and touch alternatives. Recomputed geometry, mass and CoM agree with an independent fixture. Reject occupied nodes, cycles and intersections, and keep the headless editor usable without WebGL. | Unit conventions, spec provenance, graphics dependency and device spike. |
| 2 · Earth planning and simulation | One credible funded Earth science contract from planning to closeout in text/2D. Derive visibility and eclipse from geometry. Show blocked plans with causes. Confirm propagation, energy, propellant, RF/geometry and scientific product rules against scoped fixtures. Thermal and pointing screening must carry their actual evidence status. Demonstrate command consequences through recorded events. | Phase 1 assembly snapshot, approved input versions, GMAT/SPICE and independent comparators. |
| 3 · 3D mission operations | Scene consumes worker outputs and renders state, contact and observation layers with a 2D equivalent. Playback rates yield identical final state. Test stop, seek, low-memory buffering, WebGL loss and recovery. Keep stepping and command actions usable on touch and keyboard. | Stable telemetry/event schema and recorded Earth fixture. |
| 4 · Integrated scientific verification and lunar expansion | Pass Earth contract evidence and V1 regression suites. Then add one curated lunar arrival fixture, fuel-feasible insertion, terrain survey, Earth occultation and delayed link. Verify frame/time consistency, what is excluded and end-to-end data and ledger closeout. Force high-thrust/range limits to reject unsupported scenarios. | Verified lunar initial-state/ephemeris data, terminal inputs, reviewed impulse scope and portable performance. |
| 5 · Presentation and deployment | Publish the Earth release after its gates pass. Present lunar only if its gates pass or label it planned. Verify the production build across devices, local saves and backup/restore, source/asset attribution, offline simulation assets, performance and no login. Prepare an honest demo and verify any applicable submission requirements against the portal before deployment. | Release acceptance and deployment authorization. |

**First milestone** is Phase 0. Deliver a saved agency, an auditable funding and research loop, and the headless two-body fixture workflow. It can run alongside the playable legacy tutorial. Keep rendering work behind the validated domain interfaces.

Phase 0 also establishes the source registry and fixture provenance described in the [NASA resource integration audit](NASA_RESOURCE_INTEGRATION.md). The training contract should trace at least one user deliverable to an acceptance check and a source record. Prepare the pinned Earth GM/GMAT benchmark workflow with separate provenance for the published input and the generated reference output. Later release gates require a repeatable player action and measurable outcome for each integration claimed in the submission.

## Scope and dependency decisions

- Treat reference-frame and time mismatches, invalid maneuver approximations, missed contact boundaries and mislabeled estimates as release blockers for the affected scenarios. One common event/geometry service must feed forecast, operations and review.
- Limit 3D to one small viewport at a time, with lazy loading and baseline budgets to establish on representative devices. Defer freeform CAD, launch vehicle construction, staging and elastic dynamics. Allocate as much work to engineering fixtures and science feedback as to artwork.
- Keep offline single-player saves plus export. Defer cloud sync, authentication, live ephemeris requests, multiplayer, large fleets, operational conjunction assessment, unrestricted maneuver optimization, high-fidelity thermal/pointing and advanced science retrieval. Defer atmospheric, asteroid and Mars releases until their requirements and benchmark data exist.
- Source gaps include actual launch interface and dated quote data, complete vendor part specs including operating conditions, curated ground stations and mode threshold fixtures, licensed production assets, and frozen lunar arrival, orientation and ephemeris fixtures. Exact validated operating envelopes depend on independent evidence. The SpaceX rideshare page yielded no readable pricing, a legacy USGS Landsat URL failed and the current USGS page opened. An ESA education URL failed and ESA's Types of orbits page opened. Legacy CubeSat and JPL Dataverse failures are covered by alternate official records in the [source audit](SOURCE_AUDIT.md). No private submission portal or professional hardware test data was accessed.
